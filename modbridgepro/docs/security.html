Security

ModBridge Pro B15 is designed with industrial deployment in mind. This page describes what the device protects on its own, and — just as importantly — what it expects the surrounding network to protect for it.

Web Interface Authentication

Access to the configuration interface is protected by a username and password. The default credentials are admin / admin.

Danger

Change the default credentials immediately on first login. Default credentials are publicly known; anyone on the same network can access the configuration page if the defaults are left in place.

To change credentials at any time, click the 🔒 Change Login button in the top-right corner of the configuration page.

Note

Changing your login password automatically re-secures all stored IoT credentials (MQTT passwords, Google Sheets keys) — you do not need to re-enter them after a password change.

Warning

The configuration page is served over plain HTTP with HTTP Basic authentication, so the login and everything you type into the form — Wi-Fi password, MQTT password, Google private key — cross the local network unencrypted. Configure the device over its own access point, or on a trusted network segment. Do not expose it to the internet or port-forward to it.

Credential Storage

IoT secrets are never stored in plain text on the device. The Wi-Fi password, the MQTT password and the Google Sheets private key are each encrypted before config.json is written to flash.

Cipher

AES-128-CTR, with a fresh random nonce per value

Key derivation

PBKDF2-SHA256, 2048 iterations

Key input

The device’s own MAC address and your web UI password

Binding the key to both means a flash dump on its own is not enough to recover the secrets — an attacker also needs the password you set. It also means the secrets are re-encrypted under the new key whenever you change that password, which is why they survive a password change without re-entry.

Note

Configuration files written by much older firmware, which stored these values in plain text, are still read correctly and are re-encrypted the next time you save.

Exported register maps

The Export register map button on the Modbus Devices tab writes a JSON file describing the devices, their registers and the Modbus link settings. It deliberately carries no credentials — the Wi-Fi password, the MQTT password and the Google Sheets key are all omitted — so the file can be shared with a site engineer or committed to a project repository without leaking anything.

Warning

The consequence is that an exported map is not a device backup. It cannot restore a unit on its own; the credentials have to be re-entered by hand on the replacement device. See Importing and exporting a register map.

Transport Security

Warning

Data leaves the device unencrypted in v5.0.0. MQTT publishes over plain TCP on port 1883; the TLS/SSL option in the IoT Publishing tab cannot complete a connection because no CA trust store is provisioned, and it is ignored entirely on an Ethernet uplink. Google Sheets is the exception — those uploads use the Google API client’s own HTTPS.

Plan the network around that:

  1. Isolate on a dedicated network. Place ModBridge Pro on a separate IoT or OT network, isolated from office and user devices.

  2. Keep the broker close. Run the MQTT broker on the same isolated segment, so plaintext MQTT never crosses an untrusted network.

  3. Where the data must leave the site, encrypt below the application. A site-to-site VPN or an on-site broker that forwards over TLS puts the protection somewhere the gateway does not have to provide it.

  4. Use a dedicated MQTT account. Create a dedicated MQTT user with publish-only permissions for this device. Do not use broker admin credentials — they would cross the network in the clear.

  5. Scope the Google service account narrowly. Share only the target spreadsheet with the service account. Do not reuse a key that has access to other Google resources, and rotate it if a unit is decommissioned or lost.

  6. Keep firmware updated. Apply firmware updates promptly — see Over-the-Air Firmware Update.

Physical Security

  1. Factory Reset is protected by design. The Factory Reset button (IO0) is located inside the ModBridge Pro B15 enclosure and is not accessible from the outside, preventing accidental or unauthorised resets in the field.

  2. The configuration access point closes automatically. The Wi-Fi access point is only active during configuration. It closes as soon as the device reboots after saving settings and does not reopen unless the Internet Reset button is held during the boot window.

  3. The boot window is a physical-access path. Anyone who can hold a button during the first 10 seconds after power-on can re-open the configuration access point — which is open and needs no Wi-Fi password, though the configuration page itself still requires the login. Where that matters, treat enclosure access as the control: locked panel, locked cabinet.

Time Synchronisation

ModBridge Pro synchronises its clock from pool.ntp.org at boot and every hour thereafter. All published data timestamps use IST (UTC +5:30). Accurate timestamps are important for correlating IoT data with events in process historians or ERP systems.

The offset is applied directly to the synchronised UTC clock. India observes no daylight saving, so a fixed +5:30 is exact year-round — which is why there is no time zone setting to configure and no seasonal adjustment to make.

If time has never been obtained — no internet since power-on — readings are stamped NTP Sync failed in place of a date. That marker in your data means the device was polling before it had a clock, not that the readings themselves are wrong. Buffered readings keep the timestamp from when they were taken, so a backlog arrives correctly dated once it drains.
