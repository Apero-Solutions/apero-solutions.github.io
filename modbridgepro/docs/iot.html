IoT Publishing Guide

ModBridge Pro supports two cloud publishing destinations: MQTT and Google Sheets. Both are configured on the IoT Publishing tab of the web interface.

MQTT

MQTT is the recommended protocol for real-time industrial data streams. ModBridge Pro acts as a publisher only — it does not subscribe to any topics.

Configuration parameters

Setting

Description

Broker Address

Hostname or IP of your MQTT broker (e.g., broker.hivemq.com, or the IP of a local Mosquitto instance).

Port

1883 for plain TCP, 8883 for TLS/SSL.

Username

Leave blank for anonymous connections. Stored encrypted.

Password

Leave blank for anonymous connections. Stored encrypted (AES-128).

Client ID

Unique identifier for this device on the broker. Defaults to ModBridge_ followed by the device MAC address (e.g., ModBridge_A4CF12ABCDEF). Two devices with the same Client ID will disconnect each other.

Topic

MQTT publish topic, e.g., modbridge/data. Use hierarchy for organisation: plant1/line2/gateway.

QoS

0 = fire-and-forget, 1 = at-least-once (recommended), 2 = exactly-once (slowest).

TLS/SSL

Toggle on to encrypt all traffic. Required when using port 8883.

Enable Buffering

Stores readings in PSRAM while offline; drains on reconnect. Available for both MQTT and Google Sheets.

Payload format

Data is published as a JSON object. Register names defined in the Modbus Devices tab become the JSON keys.

Example payload for two slave devices:

{
  "device_id": "ModBridgePro_A4CF12ABCDEF",
  "timestamp":  "2025-06-25T09:30:00",
  "slave_1": {
    "voltage_L1":    230.4,
    "current_L1":     12.8,
    "active_power": 2941.0
  },
  "slave_2": {
    "temperature": 24.5,
    "humidity":    61
  }
}

Tip

Use short, lowercase register names with underscores (e.g., active_power) to keep the JSON payload readable and compatible with time-series databases like InfluxDB or Grafana.

TLS/SSL setup

  1. Set Port to 8883.

  2. Toggle TLS/SSL on.

  3. Ensure the broker’s certificate chain is signed by a public CA (e.g., Let’s Encrypt). Custom CA certificates are not currently uploadable via the web UI.

Warning

If TLS is enabled but the broker certificate cannot be verified, the connection will fail silently. Use the Test Connection button before saving to confirm the broker is reachable.

Google Sheets

ModBridge Pro can append rows directly to a Google Sheets spreadsheet via the Google Sheets API using a service account. A service account is a Google identity that acts on behalf of your application — it does not require a user to be logged in.

Setting up a Google Cloud Service Account

Follow these steps once to create the service account and obtain the credentials required by ModBridge Pro.

Step 1 — Create a Google Cloud project

  1. Go to Google Cloud Console and sign in with your Google account.

  2. Click the project drop-down at the top and select New Project.

  3. Give the project a name (e.g., ModBridgePro) and click Create.

Step 2 — Enable the Google Sheets API

  1. In the left menu go to APIs & Services → Library.

  2. Search for Google Sheets API and click on it.

  3. Click Enable.

Step 3 — Create a Service Account

  1. Go to APIs & Services → Credentials.

  2. Click + Create Credentials and choose Service Account.

  3. Enter a name (e.g., modbridge-sheets) and click Create and Continue.

  4. Under Grant this service account access to project, select the role Editor and click Continue, then Done.

Step 4 — Generate a Private Key

  1. On the Credentials page, click on the service account you just created.

  2. Go to the Keys tab and click Add Key → Create new key.

  3. Select JSON and click Create. A .json file will download automatically — keep it safe, this is your only copy.

  4. Open the downloaded file. You will need two values from it:

    • client_email — this is your Service Account Email (e.g., modbridge-sheets@your-project.iam.gserviceaccount.com).

    • private_key — this is your Private Key, a long block of text starting with -----BEGIN PRIVATE KEY-----.

Step 5 — Create and share the Google Sheet

  1. Go to Google Sheets and create a new spreadsheet.

  2. Click Share (top-right corner).

  3. Paste the Service Account Email from Step 4 into the share field.

  4. Set the permission to Editor and click Send.

  5. Copy the Spreadsheet ID from the URL:

    https://docs.google.com/spreadsheets/d/<SPREADSHEET_ID>/edit

    The long alphanumeric string between /d/ and /edit is the Spreadsheet ID.

Step 6 — Enter credentials in ModBridge Pro

Open the IoT Publishing tab in the ModBridge Pro B15 configuration page and fill in:

  • Service Account Email — the client_email value from the JSON file.

  • Spreadsheet ID — copied from the sheet URL in Step 5.

  • Private Key — the full private_key value from the JSON file, including the -----BEGIN PRIVATE KEY----- and -----END PRIVATE KEY----- lines.

Warning

The private key JSON file downloaded in Step 4 grants full access to your Google Sheets API. Do not share it or commit it to version control. ModBridge Pro encrypts the key before storing it on the device.

Google Sheets parameters

Setting

Description

Service Account Email

The @developer.gserviceaccount.com email from your Google Cloud service account. This account must have Editor access on the target spreadsheet.

Spreadsheet ID

The alphanumeric ID in the Google Sheets URL: https://docs.google.com/spreadsheets/d/**<ID>**/edit

Private Key

The full private key from the service account JSON file, including the -----BEGIN PRIVATE KEY----- and -----END PRIVATE KEY----- lines. Stored encrypted on the device.

Output Format

Tabular — one column per register (best for charts and pivot tables).
JSON — each row contains the full JSON payload.

Warning

The sheet grows continuously. Older rows are cleaned up automatically when the sheet reaches a large size, but periodically archiving data to a separate sheet is recommended for long-running deployments.

Publish Interval

Both MQTT and Google Sheets use the same global Update Interval field (1–900 seconds). This governs how often a new data record is pushed to the cloud. The Modbus polling loop on Core 0 runs at the same cadence.

Offline Buffering

When buffering is enabled and the internet is unavailable, new Modbus readings are stored internally (8 MB). When connectivity is restored the buffer is drained oldest-first. The table below shows how long data can be buffered for a single device at a 1-minute publish interval:

Registers configured

Days of data buffered

1 register

~65 days

5 registers

~13 days

10 registers

~7 days

20 registers

~3 days

50 registers

~1 day

When the buffer is full, the oldest entry is overwritten automatically.

Note

Buffering works for both MQTT and Google Sheets. For Google Sheets, all buffered readings are sent as a single batch when the connection is restored.

Best practice for reliable data delivery:

  • Use QoS 1 (at-least-once delivery).

  • Enable buffering.

  • Set the update interval to a value that produces a buffer fill time greater than your typical outage duration.
